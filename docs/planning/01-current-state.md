# 01. Current State & Research

## 1. 조사 범위

- 참고 서비스: [AOI Alpha](https://www.aoialpha.com)
- 조사 방식: 공개 라우트·메뉴·로그인 게이트 브라우저 확인
- 조사 시점: 2025-09-19 fixture 기준 로컬 실행 화면 확인
- 코드 상태: `public/index.html`, `public/styles.css`, `public/app.js` 기반 Node 정적 데모 구현 상태
- 브라우저 확인: `/#/market`, `/#/stocks/005930`
- 기존 산출물: `CONTEXT.md`, `docs/stock-platform-*.md`, `docs/planning/*`

### 근거 구분

- **사실/관찰:** 조사 세션에서 확인한 라우트·메뉴·로그인 게이트와 현재 저장소의 문서 상태
- **해석/가설:** 관찰을 바탕으로 신규 제품에 적용할 수 있다고 제안한 UX 방향
- **미검증:** 실제 고객 선호·지불 의사·공급자 SLA·법무 적합성·알고리즘 성능

## 2. 현재 구현 화면 감사

### 확인한 시장 화면

- 상단 브랜드·전역 검색·방문자/무료 회원/구독자 전환·sandbox 로그인·구독 계정 액션이 한 줄에 배치된다.
- 좌측 `WORKSPACE` 사이드바와 4개 내비게이션 항목이 고정된다.
- 시장 요약과 종목 표, 신호 안내, 제품 범위가 모두 흰 카드 안에 들어간다.
- 장점: skip link, 시맨틱 heading/region/table, 기준 시각·source·신선도 표시, 모바일 하단 탭.

### 확인한 종목 상세 화면

- 제목/관심 추가 → quote summary → 가격 흐름 → 재무/뉴스 보조 열 → 실시간 신호/수급 → 출처·위험 고지 순서다.
- 로그인/구독 게이트와 `REALTIME`, `STALE` 상태는 구현되어 있으나, 같은 파란 정보 박스와 둥근 카드가 반복된다.
- 차트가 넓은 빈 영역을 차지하고, 핵심 수치·시장 맥락·신호 상태가 한 번에 스캔되지 않는다.

### 리디자인 문제 진술

1. **시장성이 약함:** 시세판·테이프·시장 breadth 등 주식 도메인의 시각 단서가 없다.
2. **위계가 평평함:** 모든 카드가 같은 테두리/배경/반경을 사용해 중요도와 읽는 순서가 약하다.
3. **정보 밀도 불균형:** 데이터 테이블은 조밀한 반면 안내 카드와 차트 주변은 과도하게 비어 있다.
4. **상태 반복:** freshness/source/demo 문구가 각 블록에서 길게 반복되어 핵심 수치의 주의를 빼앗는다.
5. **반응형 전환:** 모바일 하단 탭은 있지만 데스크톱 명령 구조와 모바일 우선 작업 순서의 차이가 충분히 드러나지 않는다.

## 3. 참고 서비스에서 확인한 라우트

- 공개: `/`, `/market`, `/login`
- 회원 전용 게이트 확인: `/focus`, `/screener`, `/reports`, `/insights`, `/picks`, `/watchlist`, `/alerts`, 종목 상세
- 기존 메뉴 개념: 시장, 관심/추천 종목, 스크리너, 리포트, 인사이트, 알림, 관심종목

접근 권한과 실제 데이터 정책은 참고 서비스의 패리티 분석 자료를 기반으로 한 것이며, 신규 제품의 최종 요구사항은 본 문서 세트가 우선한다.

## 4. 현재 사용자 경험의 관찰

### 확인된 장점

- 시장·종목·스크리너·인사이트를 분리한 정보 구조
- 로그인 전에도 제품 성격을 이해할 수 있는 공개 진입점
- 회원 전용 영역으로 가치 있는 분석 기능을 구분
- 금융 데이터 중심의 높은 정보 밀도

### 확인된 한계와 리뉴얼 기회

- 가격·수급·뉴스·재무·신호 근거를 하나의 판단 흐름으로 연결할 필요
- 지연/실시간 여부와 기준 시각을 화면 공통 요소로 강화해야 함
- 신호가 잠겨 있을 때 권한·근거·구독 가치가 더 명확해야 함
- 장애·오류·빈 상태·데이터 지연에 대한 일관된 설계 필요
- 사용자가 참고 서비스의 여러 메뉴를 왕복하지 않도록 작업 중심 IA 필요

## 6. 확정된 도메인 제약

- 국내 거래소 상장 개별주식 중심
- ETF·ETN·펀드 제외
- 주문이나 계좌 상태를 저장·변경하지 않음
- 실시간 시세와 실시간 알고리즘 신호를 핵심 가치로 삼음
- 신호는 구독 권한 검증 후 제공
- 현재 상태와 append-only 신호 이력을 분리
- `eventId`와 `(streamKey, epoch, sequence)`로 이벤트 멱등·순서를 관리하며, snapshot 이후 gap 복구 계약이 필요

## 7. 조사 한계

- Firecrawl 조회는 크레딧 부족으로 실행하지 못함
- 공급자 계약, 가격, 법무 해석, 알고리즘 정확도는 공개 자료로 확정할 수 없음
- 실제 고객 인터뷰·사용성 테스트 데이터는 아직 없음
