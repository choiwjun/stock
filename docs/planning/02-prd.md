# 02. PRD — Product Requirements Document

## 문서 상태

- 제품 요구사항 정본
- 상태: 범위 강화본 / 가격·공급자·법무 승인 전
- 구현 전에 `decision-log.md`의 제안·미결정을 승인한다.

## 1. 제품 개요

국내 개별주식 투자자가 시장을 탐색하고 종목을 분석하며, 활성 월 구독자는 실시간 알고리즘 신호와 당시 근거를 확인하는 반응형 웹 서비스다. 주문·계좌·자동매매 서비스가 아니다.

## 2. 사용자 문제와 가설

- 정보가 여러 화면과 서비스에 흩어져 있다.
- 실시간성, 신호 발생 시각, 알고리즘 버전이 불명확하다.
- 유료 기능의 가치와 제한이 불투명하다.
- 지연·장애 상황에서 어떤 데이터를 믿어야 하는지 알기 어렵다.

가설은 고객 인터뷰와 프로토타입 테스트로 검증한다. 현재 문서의 성공 지표는 기준선이 아니라 측정 설계가 필요한 제안값이다.

## 3. 사용자 스토리

- 방문자로서 서비스 가치와 무료/프리미엄 차이를 이해하고 싶다.
- 회원으로서 종목을 검색하고 관심종목에 저장·재방문·삭제하고 싶다.
- 사용자로서 가격·거래량·수급·뉴스·재무를 종목 단위로 확인하고 싶다.
- 구독자로서 실시간 신호의 발생 시각, 알고리즘 버전, 근거, 유효기간을 확인하고 싶다.
- 구독자로서 신호 만료·중단·취소·검증중 상태를 구분하고 싶다.
- 구독자로서 해지·환불·결제 실패 후 권한이 언제 끝나는지 알고 싶다.
- 사용자로서 데이터 지연·연결 끊김·권한 부족을 이해하고 복구하고 싶다.
- 장중 사용자로서 지금 시장에서 무엇이 움직이는지 첫 화면에서 빠르게 훑고 싶다.
- 분석 사용자로서 종목 상세에서 가격과 근거의 관계를 한 화면 흐름으로 이해하고 싶다.

## 4. 범위 동결

### MVP 포함

시장 개요, 종목 검색, 대표 종목 상세, 시세/차트/수급/뉴스/재무, 관심종목 CRUD, 구조화 조건 스크리너, 회원/간편로그인, 월 구독 sandbox 및 승인된 결제 연동, 구독자 신호, 실시간 장애 상태를 포함한다.

### MVP 비활성 또는 후속

자연어 스크리너, AI 점수, 사용자 저장 필터, 고도화된 성과 대시보드, 다국어, 외부 알림은 MVP 계약에 포함하지 않는다. 화면에 노출하려면 별도 PRD ID·권한·데이터·법무 승인을 추가한다.

### 제외

주문, 계좌, 포트폴리오, 모바일 네이티브 앱, ETF·ETN·펀드, 종목 비교는 구현하지 않는다.

비구독자 응답은 방향 필드 제거만으로 보호하지 않는다. 방향을 유추하는 필터·정렬·집계·차트 마커·정확한 발생 시각·캐시를 동일 권한 정책으로 제한한다.

## 7. 신호 공개 계약

- 방향: `BUY`, `SELL`, `NEUTRAL`은 법무 승인 전 내부 enum이다.
- 상태: `ACTIVE`, `SUSPENDED`, `EXPIRED`, `CANCELLED`, `VALIDATING`.
- `SUSPENDED`는 엔진 장애/데이터 신선도 문제를 포함하며 과거 방향을 최신 추천처럼 의미하지 않는다.
- `CANCELLED`는 잘못된 계산·정정 등 명시적 철회이고 `EXPIRED`는 유효기간 종료다.
- 신호 변화 이벤트와 내부 평가 revision은 분리한다.

## 8. 비기능 요구사항

- 반응형: 모바일·태블릿·데스크톱 핵심 경로
- 접근성: WCAG 2.2 AA 목표와 테스트 가능한 수용 기준
- 신뢰성: 이벤트 중복·역순 방지, snapshot cursor/replay, 권한 회수
- 보안: 서버 권한·소유권 검증, 웹훅 검증, 최소 개인정보
- 관측성: 수집·계산·발행·전송·권한 회수 지연 측정
- 성능: 공급자 SLA 측정 후 p95/p99·동시 사용자·신선도 목표를 승인

## 10. 출시 차단 조건

가격·환불·신호 유효기간·성과 산정·공급자 라이선스·법무 문구·권한 회수·개인정보 보존 정책이 승인되지 않으면 상용 결제와 실제 프리미엄 신호를 공개하지 않는다.
