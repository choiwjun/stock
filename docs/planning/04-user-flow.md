# 04. User Flow

## 1. 흐름 상태 규칙

- 인증 상태, entitlement 상태, 데이터 신선도, 작업 상태를 서로 다른 축으로 표시한다.
- 결제 성공 화면만으로 권한을 활성화하지 않는다. 서버 entitlement 확인 후 신호 화면으로 복귀한다.
- 사용자가 새로고침·뒤로가기·다중 탭을 사용해도 중복 결제나 권한 오표시가 없어야 한다.

## 1a. 리디자인 표현 규칙

행동 흐름과 권한 전이는 변경하지 않는다. 다만 시장 진입 시 `시장 테이프 → 시장 레이더 → movers → 검색/종목 상세` 순으로 시선을 유도하고, 종목 상세에서는 `quote strip → 가격 흐름 → signal dossier → 근거/상태` 순으로 같은 작업을 표현한다. 가로 테이프와 상단 명령 바는 기존 route를 바꾸지 않으며 모바일에서는 하단 탭으로 동일 목적지에 도달한다.

## 2. 방문자·회원·종목 분석

```mermaid
flowchart TD
  A[홈 방문] --> B{로그인}
  B -->|비회원| C[공개 시장/제품 가치]
  B -->|회원| D[시장]
  C --> E[검색 또는 시장 카드]
  D --> E
  E --> F[종목 상세]
  F --> G[가격·차트·수급·뉴스·재무]
  G --> H{관심목록 권한}
  H -->|회원| I[추가/중복/저장 실패 안내]
  H -->|비회원| J[로그인 후 원래 종목 복귀]
  F --> K{신호 권한}
  K -->|비구독| L[방향 없는 잠금 미리보기]
  K -->|구독| M[신호·근거·이력]
```

## 3. 로그인과 세션

```mermaid
flowchart TD
  A[로그인 선택] --> B[간편로그인 provider]
  B --> C{결과}
  C -->|취소/실패| D[원인·재시도·원래 화면]
  C -->|성공| E[약관·개인정보 동의]
  E -->|거절| F[계정 생성하지 않음]
  E -->|동의| G[세션 발급]
  G --> H[원래 작업 복귀]
  H --> I{세션 만료}
  I --> J[보호된 요청 거부·로그인 안내·return URL]
```

## 4. 관심목록 P0 흐름

```mermaid
flowchart TD
  A[종목 상세] --> B[관심 추가]
  B --> C{서버 결과}
  C -->|성공| D[저장됨 표시]
  C -->|이미 저장| E[중복 없음·현재 상태 표시]
  C -->|실패| F[재시도·오류 ID]
  D --> G[관심목록 이동]
  G --> H[재방문·시세 상태 확인]
  H --> I[삭제]
  I --> J{확인}
  J -->|예| K[삭제됨·목록 갱신]
  J -->|아니오| H
```

## 5. 구독·결제 전체 생명주기

```mermaid
flowchart TD
  A[잠긴 신호/구독 메뉴] --> B[상품·가격·자동갱신·환불 고지]
  B --> C[checkout idempotency key로 결제 시작]
  C --> D{결제 결과}
  D -->|취소/실패| E[실패 이유·재시도·원래 화면]
  D -->|성공 화면| F[pending: 웹훅 검증 대기]
  F --> G{서버 entitlement}
  G -->|활성| H[신호 복귀]
  G -->|지연| I[처리중·새로고침·문의]
  H --> J{사용자 선택}
  J -->|해지| K[해지 예정·종료 시각 표시]
  J -->|환불/지원| L[정책·문의 흐름]
  K --> M[종료 시각 권한 회수]
  L --> N[환불 웹훅·권한 전이]
  N --> M
  M --> O[열린 스트림 revoke·잠금 화면]
```

## 6. 실시간 흐름과 복구

```mermaid
flowchart TD
  A[구독자 진입] --> B[entitlement 확인]
  B --> C[stream subscribe + snapshot cursor]
  C --> D{수신}
  D -->|정상| E[streamKey/epoch/sequence 검증]
  E --> F{연속성}
  F -->|정상| G[UI 반영]
  F -->|중복/역순| H[무시·메트릭]
  F -->|gap| I[replay/resync 요청]
  I --> J{복구 가능}
  J -->|예| C
  J -->|아니오| K[전체 스냅샷·stale 표시]
  D -->|연결 끊김| L[백오프 재연결]
  L --> C
  D -->|entitlement revoke| M[스트림 종료·잠금·권한 상태 갱신]
```

## 7. 오류·복구 규칙

| 상황 | 상태 | 복구 |
|---|---|---|
| 검색 결과 없음 | empty | 검색어 수정 |
| 로그인 만료 | auth-required | 재로그인 후 return URL |
| 결제 처리중 | payment-pending | 상태 조회/문의, 중복 결제 금지 |
| 결제 실패 | payment-failed | 공급자 사유·재시도 |
| 구독 해지 예정 | cancellation-scheduled | 종료 시각·재개 정책 표시 |
| 환불 처리중 | refund-pending | 권한 정책에 따라 잠금/유지 표시 |
| 스트림 gap | resync-required | replay 또는 snapshot |
| 공급자 지연 | stale | 마지막 정상 시각·재시도 |
| 서버 오류 | error | requestId·재시도·문의 |

## 8. 흐름 수용 기준

- PRD-001~011 각각 진입·성공·실패·복구 화면이 있다.
- 결제 결과와 entitlement 활성화가 분리되어 있다.
- 관심목록은 추가뿐 아니라 재방문·삭제까지 검증한다.
- 권한 회수 후 열린 스트림에서 프리미엄 이벤트가 더 이상 전달되지 않는다.
