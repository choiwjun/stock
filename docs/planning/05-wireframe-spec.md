# 05. Wireframe Specification

## 문서 상태

- 상태: `SIGNALLAB RESEARCH DESK V2` 전면 리디자인 승인 / 구현 핸드오프
- 목적: 색상·장식보다 콘텐츠 우선순위, 화면 구조, 상호작용, 반응형 동작을 고정한다.
- 정본 관계: `06-design-plan.md`가 시각 시스템을, `07-trd.md`와 `08-api-data-contract.md`가 데이터 동작을 정의한다.

## 1. 공통 프레임

### 데스크톱

- 1440px 이상: 232px 고정 작업 내비게이션 + 본문 영역.
- 1024–1439px: 208px 내비게이션, 본문은 8/4 또는 7/5 열로 재배치.
- 상단 64px: 브랜드, 전역 검색, 장 상태, 계정 메뉴만 배치.
- 시장 상태 rail 40px: 장 상태, KOSPI/KOSDAQ, 거래대금, 데이터 기준 시각.
- 본문 최대 폭 1440px, 좌우 패딩 24–40px.
- sidebar·topbar·시장 rail은 콘텐츠를 가리지 않도록 고정 높이를 예약한다.

### 모바일

- 56px 상단 바 + 내부 스크롤 시장 rail + 시장 rail 아래의 64px sticky 작업 탭.
- sidebar는 숨기고 `시장 / 시그널 / 관심종목 / 검색`을 sticky 작업 탭으로 제공한다. 화면 하단 고정 overlay는 콘텐츠를 가리므로 사용하지 않는다.
- 페이지 전체 가로 스크롤은 금지한다. 표·시장 rail·탭만 내부 스크롤을 허용한다.
- 320px 폭, 200% 확대, 터치 입력, safe-area를 기준으로 한다.

## 2. 시장 화면 `/market`

### 데스크톱 구조

```text
[Sidebar] [Topbar: 로고 | 검색 | 장 상태 | 계정]
          [Market rail: 장중 | KOSPI | KOSDAQ | 거래대금 | 기준 시각]
          [H1 오늘 시장] [기준 시각 / 데이터 상태]
          [Market Pulse: KOSPI] [KOSDAQ] [시장 폭: 상승/보합/하락]
          [거래대금·수급 요약] [데이터 상태·출처]
          [Movers: 상승 상위 | 하락 상위 | 거래량 상위]
          [시장 흐름 표 + 미니 그래프]
          [검색으로 종목 찾기] [조건 스크리너 진입]
```

우선순위:
1. 현재 장 상태와 기준 시각
2. 시장 방향과 breadth
3. 지금 움직이는 종목
4. 사용자가 고를 다음 행동

### 모바일 구조

```text
[브랜드 | 검색 | 연결 상태]
[가로 market rail]
[오늘 시장 / 장 상태]
[KOSPI + KOSDAQ]
[시장 폭]
[거래대금]
[움직이는 종목 3개]
[전체 보기 / 종목 검색]
[sticky 작업 탭]
```

- Market Pulse의 숫자는 세로로 쌓고, 비교 기준을 각 숫자에 붙인다.
- Movers는 행 기반 semantic table을 유지하되 모바일에서는 순위·종목·가격·등락률·신선도를 한 행의 compact grid로 재배치한다.
- 핵심 판단 열을 숨기지 않으며, 출처 보조 문구만 축약한다.

## 3. 종목 상세 `/stocks/:ticker`

### 데스크톱 구조

```text
[Sidebar] [Topbar]
          [Stock identity: 종목명·코드·시장·관심 추가]
          [Freshness rail: 실시간/지연/오래됨 · 기준 시각 · 출처]
          [Quote lead: 현재가·등락·거래량·세션 고저]
          [Local tabs: 개요 | 차트 | 수급 | 뉴스 | 재무 | 신호]
          [Chart + data table, 8 columns] [Signal dossier, 4 columns]
          [Flows] [News / filings]
          [Financial snapshot] [Risk disclosure / source]
```

- 현재가와 등락은 첫 화면의 가장 큰 수치지만 신호 방향보다 앞서지 않는다.
- 차트는 항상 텍스트 요약과 표 대체 경로를 함께 제공한다.
- 신호 dossier는 구독자에게 근거와 이력을, 비구독자에게 방향 없는 가치 설명만 제공한다.
- 종목 탭은 화면 내 anchor 이동이며 URL hash 또는 접근 가능한 탭 상태를 유지한다.

### 모바일 구조

```text
[종목명·관심]
[상태·기준 시각]
[현재가·등락·거래량]
[기간 선택]
[차트 요약 + 데이터 표]
[신호 권한 상태]
[수급]
[뉴스]
[재무]
[고지]
```

- desktop의 오른쪽 패널을 단순 축소하지 않고 본문 순서에 합친다.
- sticky 탭은 사용하지 않는다. 현재 섹션은 heading·anchor·접근성 상태로 표시한다.

## 4. 시그널 `/signals`

- 구독자: 연결 상태 → 필터 → 이벤트 목록 → 근거 확장.
- 비구독자: 신호 기능의 목적·구독 가치·권한 안내만 표시.
- 실제 방향·강도·정확한 발생 시각·방향을 추론할 수 있는 정렬/집계는 비구독자에게 제공하지 않는다.

## 5. 스크리너 `/screener`

```text
[조건 선택] → [적용된 조건] → [결과 기준 시각] → [결과 표] → [종목 상세]
```

MVP는 사전 승인된 구조화 조건만 제공한다. 자연어 검색과 저장 필터는 만들지 않는다.

## 6. 관심종목 `/watchlist`

- empty: 관심종목을 추가하는 방법 + 검색 CTA.
- populated: 종목명·현재가·등락·freshness·마지막 갱신.
- saving/saved/duplicate/error/delete-confirm/delete-success를 구분한다.
- 회원이 아니면 로그인 후 원래 ticker로 돌아온다.

## 7. 공통 상태 와이어프레임

모든 주요 화면은 아래 상태를 별도로 정의한다.

| 상태 | 화면 규칙 | 사용자 행동 |
|---|---|---|
| loading | 실제 구조를 유지하는 skeleton, layout shift 최소화 | 기다림/취소 |
| empty | 결과가 없는 이유와 다음 행동 | 검색 수정/조건 완화 |
| error | 오류 내용, requestId, 재시도 | 다시 요청/문의 |
| stale | 마지막 정상 기준 시각, 최신값 아님을 명시 | 새로고침/주의 |
| unavailable | 공급자/엔진 중단 원인과 범위 | 상태 확인 |
| reconnecting | 재연결 중, 마지막 정상 수신 시각 | 기다림/수동 재시도 |
| permission-locked | 로그인 필요와 구독 필요를 구분 | 로그인/구독 |
| degraded | 일부 데이터만 이용 가능하다는 범위 | 이용 가능한 영역 계속 사용 |

## 8. 접근성 주석

- 화면마다 H1은 하나만 둔다.
- 표는 `caption`, `thead`, 행/열 헤더를 제공한다.
- 차트는 동일 데이터의 텍스트 요약과 표를 제공한다.
- 상태 변경만 `aria-live="polite"`로 알리고 가격 전체 갱신을 읽지 않는다.
- 모든 탭·필터·검색·관심 추가·재시도는 키보드로 실행할 수 있다.
- 포커스 링은 어두운 배경에서 3:1 이상 식별되며 sticky chrome에 가려지지 않는다.
- 색상은 상승/하락·지연·오류의 유일한 전달 수단이 아니다.

## 9. 필수 프로토타입 경로

1. 시장 → 검색 → 종목 상세 → 관심 추가 → 관심목록 재방문 → 삭제
2. 종목 상세 → 잠금 신호 → 구독 → 결제 처리중 → 활성 신호
3. 구독 → 실시간 시그널 → stale → replay/resync → 권한 회수
4. 스크리너 → 구조화 조건 → 결과 → 종목 상세
5. 로그인 만료 → 재로그인 → 원래 작업 복귀
6. 결제 실패/해지 예정/환불 처리중 → 상태 이해·복구

## 10. 검증 기준

- 핵심 과제를 첫 화면에서 다음 행동을 찾는 데 5초 안에 시작할 수 있다.
- 시장→종목 상세 도달이 3번의 주요 선택 안에 가능하다.
- 320px, 키보드, 200% 확대에서 콘텐츠·포커스·버튼이 잘리지 않는다.
- 모든 정상 화면에 loading/empty/error/stale/permission 상태가 대응한다.
- 브라우저 캡처로 데스크톱·모바일의 정보 위계와 레이아웃 이동을 검토한다.
