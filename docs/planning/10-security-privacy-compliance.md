# 10. Security, Privacy & Compliance

## 문서 상태

출시 차단 기준을 포함한 보안·개인정보·법무 정본이다. 체크리스트를 작성한 것만으로 준수나 안전을 선언하지 않으며, 담당자·증빙·테스트 결과를 릴리즈 기록에 남긴다.

## 0. 리디자인 보안·접근성 경계

- 시장 테이프와 movers는 공개/회원/구독 권한에 맞는 기존 응답만 사용하며, 잠긴 신호의 방향을 색상·정렬·집계·sparkline으로 추론 가능하게 만들지 않는다.
- 클라이언트에서 freshness/source를 축약하더라도 원래 의미와 상세 설명, `aria-label`을 보존한다.
- 상승/하락 색상은 금융 의미를 전달하지만 색상 단독 보안/권한 신호로 사용하지 않는다.
- 검색어·ticker·필터·URL은 기존 입력 검증과 출력 인코딩 경계를 그대로 따른다.

## 1. 위협 모델

| 영역 | 위험 | 대응·검증 |
|---|---|---|
| 인증 | 세션 탈취, OAuth 혼동, 계정 연결 오류 | state/nonce, 안전 쿠키, 세션 회전·폐기, provider 테스트 |
| 객체 권한 | 타인 관심목록·결제·구독 접근 | 세션 사용자 기준 ownership test, IDOR 음성 테스트 |
| 프리미엄 권한 | API·스트림·캐시 우회 | field/filter/sort/aggregation/topic matrix, deny-by-default |
| 권한 회수 | 열린 연결에서 만료 후 계속 수신 | revoke fanout, TTL/권위 조회, 재연결 거부, 최대 지연 측정 |
| 결제 | 위조·중복·역순 웹훅 | 서명, provider event id, revision/권위 재조회, 상태표 테스트 |
| 입력 | 검색·스크리너·URL 주입 | schema validation, parameterized query, output encoding |
| 실시간 | 토픽 추측·재전송·gap | Origin/토픽 검증, cursor/epoch/sequence, replay 제한 |
| 공급자 | 라이선스·잘못된 최신성 | 계약·재배포 범위·SLA·source/asOf 증빙 |
| 금융 표현 | 투자 권유·수익 보장 오해 | 고지·표현·성과 기준 법무 승인 |
| 운영 | 키·개인정보 로그 노출 | secrets manager, masking, 접근 감사, secret scan |

## 2. 인증·세션

- 간편로그인 provider subject와 내부 `user_id`를 분리한다.
- access/refresh token을 브라우저 localStorage에 장기 저장하지 않는다.
- secure/httpOnly/sameSite 쿠키, CSRF 방어, 허용 Origin 검증을 적용한다.
- 로그인·로그아웃·비밀번호/연결 변경·관리자 조치 시 세션 폐기/회전 규칙을 명시한다.
- 만료 세션은 보호 API·스트림·재연결 모두 거부하고 `returnUrl`을 안전하게 검증한다.
- rate limit, 로그인 실패 보호, 지원자 인증 절차를 별도 운영 문서에 둔다.

## 3. 객체 소유권·권한

서버는 다음을 매 요청 검증한다.

- watchlist과 item의 소유 user가 세션 사용자와 같은지
- subscription/entitlement가 세션 사용자에 속하고 capability·유효기간이 맞는지
- 결제 요청의 금액·상품·사용자 ID를 클라이언트가 결정하지 않는지
- ticker·topic 접근이 존재 여부를 이용한 정보 노출을 만들지 않는지

FK는 참조 무결성일 뿐 요청자 권한 검증이 아니다. 타인 리소스 ID를 사용한 403/404 정책과 음성 테스트를 정한다.

## 4. 프리미엄 신호 보호

- 실제 방향·강도·근거·버전·정확한 발생 시각은 활성 entitlement에서만 제공한다.
- 무료 응답의 필터·정렬·집계·차트 marker·캐시가 방향을 유추하게 하지 않는다.
- API와 gateway는 각각 entitlement를 검증한다. 클라이언트 숨김은 보안 경계가 아니다.
- revoke 이후 열린 연결에는 premium payload를 더 이상 보내지 않는다. 버퍼·재전송·재연결도 검사한다.
- 권한 검증 및 회수 실패는 기본 거부이며, 최대 회수 지연을 출시 목표로 측정한다.

## 5. 결제 보안과 전이

- provider 서명·timestamp·endpoint를 검증하고 원문 요청을 무제한 저장하지 않는다.
- `Idempotency-Key`와 provider event ID를 분리한다.
- 성공 redirect는 pending 화면만 만들며, webhook/권위 조회 후 entitlement를 활성화한다.
- 결제·자동갱신·해지예정·환불중·환불완료·실패·만료를 별도 상태로 기록한다.
- 역순/중복 이벤트가 오래된 상태로 권한을 부활시키지 못하게 revision 또는 provider 재조회를 사용한다.
- 카드번호·CVV·access token을 저장하지 않는다.

## 6. 개인정보 및 보존

최소 수집 원칙을 적용한다: 로그인 식별자, 계정 상태, 구독 상태, 관심목록, 운영에 필요한 감사 정보. 수집 목적·필드·보존 기간·삭제 방식·제3자 제공·국외 이전·처리 위탁을 개인정보 문서와 데이터 사전에 연결한다.

`docs/planning/09-database-design.md`의 보존 표를 승인 전 채운다.

- 탈퇴 요청의 즉시 삭제/익명화 대상과 법정 보존 예외 분리
- 백업·read replica·캐시·로그에 삭제가 재적용되는 절차
- 운영자·지원자·개발자의 역할별 접근 최소화
- raw provider payload는 필요한 필드·기간·암호화·접근 기록을 승인
- 개발/스테이징 운영 개인정보 복제 금지 또는 비식별화

## 7. 신호·금융·라이선스 출시 게이트

다음은 내부 위험 수용으로 대체할 수 없는 차단 조건이다.

- 매수/매도 표현 또는 대체 표현의 법무·컴플라이언스 승인
- 투자 권유 아님, 데이터 지연, 알고리즘 한계, 유효기간, 오류 정정 고지 승인
- 성과/백테스트 표시 시 수수료·슬리피지·생존편향·기간·벤치마크 기준 승인
- 시세·뉴스·재무 재배포권, 사용 범위, attribution, SLA 증빙
- 공급자 변경·라이선스 만료·알고리즘 버전 변경 시 재검토 조건
- 미승인 실데이터·신호·성과의 외부 노출 금지

## 8. 애플리케이션 보안 기준

OWASP ASVS와 API Security Top 10을 기준으로 다음을 CI/릴리즈에 연결한다: CORS allowlist, CSP/HSTS/security headers, 입력/출력 검증, rate limit, 오류 정보 최소화, dependency/container/secret scan, 관리자 MFA·감사 로그, API 권한 매트릭스 테스트.

## 9. 사고 대응·증빙

인증, 결제, 프리미엄 권한, 잘못된 신호, 공급자 장애·라이선스 사고별 runbook을 만든다. 키 폐기·교체, 세션 무효화, 권한 일괄 회수, 신호 correction/공지, 사용자·공급자·관계기관 통지 책임자를 지정한다. 각 릴리즈에는 테스트 결과·승인자·문구 버전·라이선스 문서·잔여 위험을 첨부한다.

## 10. 미결정 책임

- 법무/컴플라이언스: 신호 표현·고지·성과
- 보안: 인증·권한·결제·침투 테스트
- 개인정보: 수집·보존·탈퇴·백업 삭제
- 데이터: 공급자 계약·재배포·SLA
- 운영: 권한 회수·장애·복구·고객지원
