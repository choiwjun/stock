# 주식 플랫폼 리뉴얼 디자인 기획 v0.1

> **정본 안내:** 이 문서는 디자인 방향 참고자료다. 정본은 [`docs/planning/06-design-plan.md`](planning/06-design-plan.md)와 [`docs/planning/05-wireframe-spec.md`](planning/05-wireframe-spec.md)다. 최종 토큰·상태·접근성·프로토타입 통과 여부는 planning 문서와 승인 기록으로 판단한다.

## 1. 디자인 리드

이 제품은 매매창이 아니라 **신뢰할 수 있는 금융 리서치 터미널**이다. 초보자도 시장을 읽을 수 있고, 숙련자는 근거와 신호 이력을 빠르게 검증할 수 있어야 한다.

디자인 목표:

- 신호를 자극적으로 판매하지 않고 근거와 함께 보여준다.
- 데이터 밀도는 높이되 첫 판단 경로는 단순하게 만든다.
- 실시간성·지연·오류를 숨기지 않는다.
- 월 구독 전환은 과장보다 제품 가치 체험으로 설득한다.

### 디자인 다이얼

```text
정보 밀도: 높음
시각적 장식: 낮음
신뢰감: 높음
모션: 낮음
개성: 절제된 금융 터미널
초보자 접근성: 높음
```

## 2. 디자인 원칙

### 1) 근거가 신호보다 먼저 이해되어야 한다

매수·매도 상태만 크게 노출하지 않고 발생 시각, 알고리즘 버전, 긍정 요인, 위험 요인을 같은 맥락에 둔다.

### 2) 요약에서 원자료로 점진적으로 내려간다

시장 브리핑 → AI 점수 → 신호 근거 → 차트·수급·재무·뉴스 순서로 탐색한다.

### 3) 실시간 데이터는 상태를 가진다

`실시간 연결됨`, `지연`, `재연결 중`, `마지막 정상 수신`을 항상 명확하게 표현한다.

### 4) 색상만으로 판단을 강요하지 않는다

매수·매도·중립은 색상, 텍스트, 아이콘, 패턴을 함께 사용한다. 차트와 표에서도 동일하다.

### 5) 프리미엄 잠금은 제품을 가리지 않는다

무료 사용자에게는 시장과 종목의 가치를 충분히 보여주고, 유료 신호 영역만 명확하게 잠근다. 과도한 블러나 오해를 부르는 미리보기는 사용하지 않는다.

### 6) 카드 모음보다 정보 구조를 우선한다

모든 콘텐츠를 같은 둥근 카드로 만들지 않는다. 표·섹션·고정 헤더·구분선·탭을 정보의 관계에 맞춰 사용한다.

## 3. 시각 방향

### 기본 모드

기존 서비스의 다크 모드 토글을 유지하되, 데이터 터미널 성격상 다크 모드를 우선안으로 검토한다. 라이트 모드도 동일한 의미와 대비로 제공한다.

### 색상 토큰 초안

최종 브랜드 컬러 확정 전의 제품 토큰 후보다.

```text
Graphite  #0B1117  기본 배경
Surface   #121A23  패널·표면
Line      #273440  구분선·테이블 선
Text      #F2F5F7  기본 텍스트
Muted     #9BAAB5  보조 텍스트
Signal    #42C7C1  브랜드·정보 강조
Positive  #39C98A  상승·매수 의미
Negative  #F07878  하락·매도 의미
Warning   #F0B35B  지연·주의
Info      #78A9E8  안내·링크
```

사용 규칙:

- Signal은 브랜드와 인터랙션 강조에 사용한다.
- Positive·Negative는 상태 표현에만 사용하고 장식에 사용하지 않는다.
- 텍스트 대비는 일반 텍스트 4.5:1 이상, 큰 텍스트 3:1 이상을 목표로 한다.
- 다크·라이트 모드에서 semantic role을 유지한다.
- 실제 적용 전 색각 이상 시뮬레이션과 대비 검사를 진행한다.

## 4. 타이포그래피

### 후보

- 한국어 UI: Pretendard 또는 SUIT
- 숫자·시세·코드: IBM Plex Mono 또는 동일 폭 숫자

### 역할

```text
H1: 화면 목적을 짧게 설명하는 제목
H2: 시장·신호·분석 섹션 제목
Body: 설명·뉴스·고지
Data: 현재가·등락률·점수·시각
Meta: 기준일·출처·알고리즘 버전
```

숫자는 우측 정렬과 tabular figures를 사용한다. 등락률·가격·시간의 자릿수 변화로 레이아웃이 흔들리지 않아야 한다.

## 5. 레이아웃 원칙

### 데스크톱

- 12컬럼 그리드
- 고정 헤더와 시장 상태 스트립
- 본문 최대 폭은 데이터 표와 분석 문장이 함께 읽히는 수준으로 제한
- 시장·시그널 화면은 2열 구조를 허용하되 핵심 표는 충분한 가로 폭을 확보

### 모바일

- 2열 대시보드는 세로 순서로 재배치
- 시그널 테이블은 종목 카드로 변환
- 차트와 데이터 표는 가로 스크롤을 최소화하고 핵심 수치를 먼저 제공
- 고정 하단 탭은 화면 깊이가 깊어질 때만 검토

### 우선순위

```text
실시간 상태
→ 현재 판단
→ 근거
→ 원자료
→ 부가 탐색
```

## 7. 화면별 디자인 강조점

### 시장 대시보드

첫 시선은 지수와 세션 상태, 두 번째는 시장 브리핑, 세 번째는 실시간 시그널이다. 시장을 장식적인 히어로로 만들지 않는다.

### 실시간 시그널

신호 상태보다 종목·현재가·발생 시각·근거를 함께 비교할 수 있어야 한다. 표의 행 높이는 정보 밀도와 터치 영역을 균형 있게 잡는다.

### 종목 분석

상단은 현재가·AI 점수·신호를 고정하고, 근거 콘텐츠는 탭으로 분리한다. 신호 이력은 시간순으로 읽히는 구조를 사용한다.

### 조건 스크리너

자연어 입력과 구조화된 필터 사이의 변환을 시각적으로 보여준다. 시스템이 해석한 조건을 사용자가 수정할 수 있어야 한다.

### 월 구독

가격보다 “무엇을 실시간으로 볼 수 있는가”를 먼저 설명한다. 신호를 과장하거나 수익을 암시하는 카피를 사용하지 않는다.

## 8. 상태·접근성 디자인

필수 상태:

- 로딩 스켈레톤
- 결과 없음
- 시세 지연
- 실시간 재연결
- 알고리즘 처리 중
- 신호 일시중지
- 구독 잠금
- 결제 실패
- 구독 만료

접근성:

- 화면별 H1 하나
- 탭과 필터의 키보드 이동
- 명확한 포커스 링
- 차트의 텍스트 요약 또는 표 대체
- `aria-live`는 신호 상태 변경에 한정해 사용
- 모션 감소 설정 존중
- 표의 행·열 관계를 스크린리더가 이해할 수 있게 제공

## 9. 프로토타입 검증 과제

1. 사용자가 오늘 시장 상태를 10초 안에 설명할 수 있는가
2. 사용자가 가장 높은 매수·매도 신호를 찾을 수 있는가
3. 신호 발생 시각과 현재가 시각의 차이를 이해하는가
4. 무료 사용자에게 잠긴 기능과 결제 가치를 이해시키는가
5. 사용자가 종목을 관심종목에 저장할 수 있는가
6. 시세 지연 또는 연결 끊김을 오해하지 않는가

7. 클릭 가능한 프로토타입
8. 사용성 검증 결과
9. 개발 전달용 디자인 스펙

## 11. 디자인 완료 기준

- 핵심 사용자 흐름이 프로토타입으로 연결된다.
- 모든 핵심 화면에 로딩·빈 상태·오류 상태가 있다.
- 무료·프리미엄 차이가 명확하다.
- 실시간 상태와 데이터 기준 시각이 보인다.
- WCAG 2.2 AA 기준의 기본 접근성 검토를 통과한다.
- 색상·타입·간격·컴포넌트 토큰이 문서화된다.
- 개발자가 별도 해석 없이 상태와 동작을 구현할 수 있다.
